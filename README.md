# 视频制作 OS

一个以网页创作为中心的本地视频工作台：集中管理**图片与视频创作网页**、**固定提示词**、**分剧本资产中心**、**音频与 BGM**、**成片**和**项目知识**。

## v1.1.0 · 2026-09-14

- 浏览器记忆：图片／视频标签独立保存；切换大厅、资产库或重启后恢复标签与地址；支持手动清空全部网页。
- 资产中心：图片、视频、音频、BGM、音效和成片按剧本关联，支持外部文件夹索引与复制复用。
- 剪映导出接入：为每个剧本提供人物音频和成片目录，导出文件稳定后自动收录，无需再次上传。
- 创作体验：资产浮窗、拖拽小窗、文件夹折叠箭头、可收起的 BGM／音效，以及更紧凑的工具栏。
- 网页协作：资产可直接传入网页上传框；可选的 MCP 制作流程记录支持接续、引用绑定与操作回执。详见 [自动化说明](AUTOMATION.md)，不代表完整生成链路已自动化验收。
- 已精简剧本拆解、镜头台账与提示词队列；继续保留固定提示词模板。

[主项目源码](https://github.com/SJT-bright/video-production-os) · [Windows 下载](https://github.com/SJT-bright/video-production-os-windows/releases/latest)

资产中心共用同一份文件索引：本剧资产、图片与视频、音频和成片只是不同视图。工作台中的“外部来源”汇集关联目录与 Obsidian，支持图片、音频和视频；选择“用于本剧”后复制进指定剧本，源文件保持不动，重复点击不会重复复制。外部目录新文件自动刷新，BGM／音效目录中的音频自动补录到专属条目。移除音乐条目只隐藏该条目，不删除音频文件。

## 项目简介

一个以创作为中心的本地 AI 视频工作台：把图片设计、视频制作、分剧本资产整理和常用 AI 网站放进同一个 macOS 应用。图片与视频模式分别管理网页标签，资产按剧本归类，可导入、预览、复制和拖到创作网页。提示词由用户在 GPT 等网页中准备，不要求拆解文件或镜头台账。

技术栈为 Electron、Node.js、原生 HTML/CSS/JavaScript 和 SQLite。应用负责组织工作流，图像与视频生成由用户打开的第三方平台完成，不内置生成模型。

本仓库保存软件源码、界面图标、开发脚本和说明文档；不包含个人剧本、人物素材、生成结果、登录会话、本地数据库或打包后的应用。

创作浏览器会自动记住图片、视频模式各自的标签顺序、名称、网址和最后选中的标签。切换大厅或资产库时不关闭网页；退出后重开可恢复标签与地址（网站未提交的表单由网站自行保存）。顶部“清空网页”只关闭两个模式中的网页，不删除登录、网站入口或素材；清空状态也会保留，不自动补开默认网页。有下载任务时需先完成或取消下载。

### 从 GitHub 启动

需要 Node.js 22.12 或更新版本。macOS 打包目前依赖 `视频制作OS` 这个目录名，请按下面的结构克隆到一个单独的工作目录：

```zsh
mkdir -p video-production-workspace
cd video-production-workspace
git clone https://github.com/SJT-bright/video-production-os.git 视频制作OS
cd 视频制作OS
npm ci
npm run desktop
```

首次运行可创建自己的剧本或灵感工作区。个人数据会在本机生成并由 `.gitignore` 排除；素材放在工作目录下的 `创作资产库/` 和 `素材库/`。浏览器登录会话保存在 Electron 的本机用户数据目录中，不进入仓库。

```zsh
# 仅使用网页兼容版（不含桌面内嵌浏览器）
npm run browser

# 在 Apple Silicon Mac 上生成本地应用；Intel Mac 改为 --arch x64
npm run build:mac -- --arch arm64
```

个人剧本、素材和既有拆解文件均保留在原目录；应用不会因功能精简而迁移或删除它们。

## 启动

### macOS 独立 APP（主版本）

以后以 macOS 为主：在 Mac 上保留并维护完整项目目录，直接使用独立的 `视频制作 OS.app` 做图片和视频创作。它不是网页快捷方式，而是 Electron 在 **真实 Mac** 上生成的 `.app`；图片／视频工作台、素材元数据、Agent 经验和文档批注都使用该项目中的唯一 `视频制作OS/data`，`.app` 包内绝不复制这些实时数据。

1. 将完整项目目录移动或复制到目标 Mac 的本地磁盘（例如“文稿”目录）；以后直接在这份 Mac 项目里修改、测试和打包。不要只拷贝 Windows EXE 或单独拷贝 `.app`。
2. 在 Mac 安装 Node.js 22.12 或更高版本。
3. 第一次在终端进入 `视频制作OS` 后执行：

   ```zsh
   chmod +x 启动OS-mac.command 安装桌面版依赖-mac.command 启动OS-浏览器版-mac.command
   ./安装桌面版依赖-mac.command
   ```

4. Apple Silicon 自动生成 `dist/视频制作 OS-darwin-arm64/视频制作 OS.app`；Intel Mac 自动生成 `dist/视频制作 OS-darwin-x64/视频制作 OS.app`。在**未移动项目的位置**可以直接双击 `.app`；只要移动了整个项目目录、改过源码，或不确定包是否最新，就双击 `启动OS-mac.command`。启动器会先核验 `.app` 的应用主程序、Info.plist、CPU 架构以及当前源码的完整哈希清单；发现旧包、缺文件或清单不完整时会先重建，不会静默打开过时版本。孤立移动 `.app` 时应用会停止并提示使用启动器重建，绝不会在旧路径自动新建空台账。
5. 如需另一种 CPU 架构，在对应 Mac／CI 上运行 `npm run build:mac -- --arch arm64` 或 `npm run build:mac -- --arch x64`。首版提供两个薄包，不把两个架构伪装成一个 universal 包。

**创作优先启动**：日常双击 `.app` 后直接进入**创作浏览器**（上次模式、当前剧本；首次使用为图片模式），不再先经过制作 OS 主窗口；主窗口在点「返回制作 OS」或切换剧本时按需打开。

日常修改与重新打包（在 Mac 的 `视频制作OS` 目录中）：

```zsh
npm run check
npm run build:mac -- --arch arm64  # Apple Silicon
# Intel Mac 使用：npm run build:mac -- --arch x64
```

浏览器回归测试只用于开发校验；第一次需要下载 Chromium 时，先运行 `npm run setup:test-browser`，再运行 `npm run test:browser`。这不影响正式 `.app` 的使用。

非 macOS 环境只能完成源码与构建契约检查，不能生成可信可运行的 `.app`。本项目在 Mac 上构建后会执行本机 ad-hoc 签名与严格 Bundle 校验，适合当前开发 Mac 使用；要分发给其他 Mac，仍必须完成 Developer ID 签名、Apple notarization、staple 和隔离下载测试后才可发布。

> 从 Windows 首次迁移到 Mac 时，先完整退出 Windows 版本，再复制整个项目目录。迁移完成后，请把 Mac 本地目录视为唯一工作副本：不要让 Windows 与 Mac 同时写入同一份 `data`，也不要用云盘／NAS 同步 SQLite 的 WAL 文件。旧 Windows 下载记录中带绝对盘符的文件会显示为历史记录；需要打开原文件时重新关联相应素材，新的 Mac 下载会按当前项目重新归档。

### Windows 独立 APP（兼容保留）

Windows 与主仓库同步核心源码，在独立仓库分发。下载 Release 中的 `VideoProductionOS-Windows-x64.zip`，**先完整解压，再双击文件夹里的 `视频制作OS.exe`**，无需另装 Node.js。不要只移动 EXE，旁边的 DLL、resources 和 locales 都属于运行文件。

下载版的个人数据存放在 `%APPDATA%\视频制作 OS\workspace`，浏览器会话保留在同一用户配置目录，替换软件文件夹不会清空它们。源码开发仍用 `npm run desktop`，本机项目绑定构建用 `npm run build:desktop`；公开下载版用 `npm run build:windows:release`。详见 [Windows 发布说明](WINDOWS-RELEASE.md)。

## 核心工作区

### ◫ 创作浏览器
- **双模式独立网页**：图片与视频各有一组标签，分别保留网页地址、浏览历史、页面草稿及标签名称。切换模式会回到该模式最后选中的网页；新开或关闭标签只影响所在模式。同一网站仍共享登录状态，当前剧本的资产可在两种模式中复用，后台下载按来源网页的模式归档。
- **图片模式**：GPT 图片 + Gemini + Grok + Midjourney + 核绘 + LibTV；保存独立的图片提示词、提交前检查、当前平台与下载列表
- **视频模式**：GPT 提示词 + Gemini + Grok + Updream + 小云雀 + 核绘 + LibTV；保存独立的视频提示词、时长/连续性检查、当前平台与下载列表
- **固定提示词**：左栏保留「＋ 新建固定提示词」和已有条目。展开任意条目可修改标题和正文、保存修改或直接复制；固定提示词跨剧本通用，图片／视频分类保留，系统不预置模板。⌘Enter 复制当前选中的条目并切到网页。
- **资产卡复制图片**：左栏资产缩略图悬停出现「复制」，图片进剪贴板后到平台输入框直接粘贴上传参考图
- **快捷键**：`Cmd/Ctrl + 1…9` 切换多开网页标签；`Cmd/Ctrl + Enter` 复制当前提示词并切到网页；`Cmd/Ctrl + E` 导入刚下载的文件；`Cmd/Ctrl + R` 或 `F5` 刷新网页；`Cmd/Ctrl + L` 聚焦地址栏；`Cmd/Ctrl + W` 关闭当前网页；`Cmd/Ctrl + [` / `]` 后退/前进；`Cmd/Ctrl + +` / `-` / `0` 网页缩放
- **多开网页批量出图**：点顶部「＋」可为主要平台再开一个独立网页（如同时开 3 个 GPT 窗口批量生成）；同一平台的所有窗口共享一次登录；关闭最后一个标签后保留空白状态，不自动补开网页
- **网站和标签改名**：点「＋」后，用网站旁的「✎」修改网站名称，重启后仍保留；双击或右键网页标签（也可聚焦后按 F2）可单独命名，例如「人物图」「场景图」，同平台的其他标签不受影响。标签间距与留白已收紧，悬停时可直接复制标签。
- **剧本与资产互通**：图片模式和视频模式共用同一个「当前剧本」；图片端生成的图片、拖入的素材保存在该剧本的 `创作资产库/<剧本>/` 下，视频端选择同一剧本后立即可见可用，反向同理；从任一模式顶部「当前剧本」按钮切换剧本即可
- **工作台素材自动索引**：工作台上传、拖入、下载归档的图片和视频自动出现在「媒体索引」，音频自动出现在「音频素材」。既有素材也会收录，保留剧本／文件夹归属；原文件不搬动、不复制，同一文件已被手动目录索引时不重复显示。导入、改名、移动和删除会通知侧栏刷新；成片目录内的视频和手动标记的成品进入「成片库」。
- **拖拽导入 + 自动重命名**：图片/视频无论拖进创作浏览器、完整资产库，还是在平台网页里点击下载，落盘时都自动按「分类-序号」重命名（如 `生成图片-001.png`、`人物资产-007.png`），序号接续目标文件夹里的最大编号；首帧/尾帧截取保留镜头语义命名
- **资产整理**：完整资产库的每张卡支持「改名」（扩展名自动保留）和「移动到…」其他文件夹；勾选卡片左上角圆点（或 Cmd/Ctrl+点击卡片）可多选，底部操作栏提供「全选 / 批量移动 / 批量删除」；删除统一移入 macOS 废纸篓，可随时恢复
- GPT 使用同一个持久登录会话，两种模式无需重复登录；两套提示词上下文不会互相覆盖
- 工具栏地址框可直接输入完整网址或域名；省略协议时自动补 `https://`，本机 `localhost` 自动使用 `http://`；按 Enter 或点击「前往」打开
- 手动地址只允许 `http/https`，会拒绝 `javascript:`、`file:`、`data:`、超长地址和在网址中夹带账号密码的形式
- 图片、视频和音频按当前剧本归档到相应分类，完成后刷新工作台与资产中心；Obsidian 通过外部来源索引与复用
- 平台阻止内嵌登录或页面加载失败时，工作台会显示恢复条：可以重新加载、用系统浏览器继续，或把系统浏览器已经下载的文件“导入并归档”到当前图片/视频模式的目标目录
- **浏览器兼容性**：内嵌浏览器使用 Chromium，并配置网站所需的标准权限；同平台多窗口共享登录会话。第三方平台仍可能限制内嵌登录或触发人机验证，不能保证所有网站均可登录；必要时使用「系统浏览器打开」。
- GPT、Gemini、Grok、Midjourney、Updream、小云雀、核绘和 LibTV 的账号登录仍由各平台自己的页面处理；本 OS 不读取或保存账号密码。个别平台仍强制拒绝嵌入式登录时，使用工作台中的「系统浏览器打开」完成兼容流程

#### 创作时打开可复用资产库

- 主侧栏的「资产中心 → 创作资产」提供全尺寸管理视图；它与视频素材、音频素材和 Obsidian 资产处于同一一级类别，但不会移动或混合真实文件。
- 点击创作浏览器顶部的「创作资产」即可打开或关闭边栏；没有连接 Obsidian 也可独立使用。
- 默认「浮窗」临时覆盖平台右侧，不占用网页宽度；点击平台网页、切换网页标签或返回网页输入时退到后面，不始终置顶。
- 再次点击顶部「创作资产」即可恢复浮窗，保留原目录、筛选和滚动位置。也可主动选择「并排」固定左右分区；窗口变窄后仍可切换显示方式。
- 点击「展开」可切到大尺寸 Split View，也可拖动左边缘在 360–760px 范围内调宽；双击边缘恢复默认宽度。
- 一级文件夹用于区分剧本，下级文件夹可按人物、场景、色卡、音频和视频参考继续分类；真实文件保存在项目根目录的 `创作资产库`。
- 支持导入、搜索和筛选图片、音频、视频与文档；图片可缩放，音频和视频可直接播放，任何资产都可在 Finder 中定位。
- 桌面版中把资产卡直接拖到 GPT、Gemini、Grok、Midjourney、Updream、小云雀、核绘或 LibTV 的上传区域，会发起系统级文件拖放。若平台拒绝拖放，使用「定位」后从平台上传按钮继续。
- Obsidian 的只读资产索引仍保留在主界面，不会被创作资产库移动或改写。

### ◫ 同窗切换与归档

- “返回制作 OS”在当前窗口内切换页面，不新开窗口；再次进入创作时保留平台网页、登录状态和未提交内容。
- 从创作浏览器或资产浮窗切换剧本，使用同一窗口内的剧本选择器。
- 生成文件按所属剧本和图片／视频模式归档，不再要求创建镜头或关联台账。

### 📦 素材库
- 只扫描项目根目录下 `素材库` 及其子文件夹中的**视频**，不会混入 evidence、蒸馏图片或分析产物
- 素材库只显示一个来源卡；支持按名称、时间和大小排序
- 点缩略图全屏预览，视频支持拖进度条播放（Range 流式）
- 空库和工具栏均可直接选择本机视频；文件会流式导入 `素材库/手动导入/<日期>`，同名文件自动保留两份，完成后索引自动刷新
- 也可点「打开素材库文件夹」直接进入 Windows 资源管理器或 macOS Finder
- 素材可**收藏 ★**、**标记为成品**、写备注；保存在 `data/asset-meta.json`
- 人物、服装、场景与色卡等图片保存在本剧资产；既有 Obsidian 素材也可通过外部来源复用

### 🎵 音频库
- 汇总工作台、项目素材库和手动关联目录内的音频，不重复复制原文件
- 按归属剧本分组，支持名称与路径搜索、剧本筛选和多种排序
- 列表内直接播放，也可进入灯箱详情添加收藏、标签、备注或在资源管理器／Finder 中定位
- 空库和工具栏均可直接批量导入本机音频；导入进度、取消状态与单文件失败会在右下角显示
- 支持 mp3、wav、m4a、aac、flac、ogg、opus、wma、aiff/aif、amr、ape

### 剪映导出 → 本剧人物音频与成片

在「创作资产」「音频素材」或「成片库」点击 **剪映导出**，选择剧本，复制对应路径，粘贴到剪映的导出位置即可。只保留两个用途，不需要另建中转库：

```text
创作资产库/剧本名称/
├── 音频/    ← 剪映提取的人物音频，自动进入本剧音频库
└── 成片/    ← 剪映导出的最终视频，自动进入本剧成片库
```

- 人物音频复用已有「音频」目录；建议命名为 `人物名-音色参考.mp3`，也可在目录内按人物建立子文件夹。文件在创作资产库中可以试听、拖动复用。
- 归属由文件实际保存的剧本目录决定，和导出期间正在浏览哪个剧本无关。**切换剧本时，需要在剪映里更换导出路径**；本功能不会代替剪映修改设置。
- 软件运行时自动检测这些目录，文件大小和修改时间连续稳定约 4 秒后收录；MP4/MOV/M4A 检查容器索引及长度，WAV 检查声明长度。MP3 等流式音频没有导出完成信号，依靠稳定窗口判断；后续继续写入时会重新等待。
- 不复制、不移动、不删除导出文件；同一路径覆盖更新不会新增重复记录。软件关闭期间导出的文件，会在下次启动时补充索引。BGM、音效仍保留原有独立分类。

### 🗂️ Obsidian 索引
- 自动找到 Obsidian 当前打开的 Vault，并原样镜像它已有的文件夹、子文件夹和文件名称
- 只使用 Obsidian 自带的上下级关系做索引，不读取文本内容来重新分类，也不修改或移动 Vault 文件
- Markdown 笔记可在网站中阅读；`![[粘贴图片.png]]`、音频和视频等本地附件按笔记中的原始顺序显示
- 文件名搜索只负责定位已有文件，不生成额外标签或内容语义分类
- 如需固定另一座 Vault，可在启动前设置环境变量 `OBSIDIAN_VAULT_PATH`

## 其他功能

- **创作优先的精简界面**：侧栏默认只保留「图片创作、视频创作、创作资产」，其余模块（总览、媒体索引、音频素材、Obsidian 资产、成片库、项目知识、Agent 与规则、使用说明）收进「更多功能」，点击展开／收起，设置会记住
- **内容生产总览**：按真实索引展示当前项目、视频、成片、音频、知识文档和最近入库，不展示虚构示例资产
- **固定侧栏**：切换模块时保留各模块内部状态
- **成片库**：自动读取各剧本「成片」目录，也支持手动标记成片或关联指定文件夹；按剧本展示，不移动原文件
- **全局搜索**（顶部搜索框 / ⌘K）：同时搜素材文件名、项目知识和 Agent 规则
- 「在文件夹中显示」：灯箱侧栏一键用 Finder 定位文件

### 快速参与

1. Fork 本仓库
2. `git checkout -b feat/xxx`
3. 修改代码并提交：`git commit -m "feat: ..."`
4. `git push`
5. 提交 Pull Request（说明你修复的问题、复现步骤与验证方式）

建议优先包含：

- 变更影响范围（哪几个模块）
- 复现步骤或使用场景
- 是否涉及数据结构或目录约定变更
- 是否影响 macOS 打包与启动流程

### 分支与稳定性约定

- `main` 保持可运行主线
- 每次改动尽量聚焦一个目标（例如仅资产库、仅启动器、仅创建入口）
- 若改动涉及本地数据路径，请同步更新 `data` schema 与说明文档

### 社区与沟通

- 功能建议与 Bug 反馈请到 GitHub Issues 提交，附上：
  - 系统环境（macOS / Windows）

  - 复现路径、截图或视频
  - 预期与实际结果
